# VIP FOV + Weapon (CS2 / Linux)

Модифицированный вариант `VIP_FOV`: одно значение VIP FOV меняет одновременно:

- `CBasePlayerController::m_iDesiredFOV` — FOV мира/камеры;
- `CCSPlayerPawn::m_flViewmodelFOV` — FOV рук/оружия.

Оба offset'а ищутся через **SchemaSystem во время запуска**, поэтому в исходнике нет жёсткого `0x1504` и модуль не привязан к одному конкретному `libserver.so`.

## groups.ini

Можно оставить привычную настройку:

```ini
"FOV" "90,100,110,120"
```

Используются те же имена feature/cookie, что у обычного VIP_FOV:

- feature: `FOV`
- cookie: `FOV_Value`

Поэтому этот модуль задуман как замена обычному VIP_FOV, а не как вторая FOV-фича одновременно с ним.

## Как рассчитывается FOV оружия

По умолчанию используется пропорция от стандартных значений world=90 и viewmodel=68:

```text
90  -> 68.00
100 -> 75.56
110 -> 83.11
120 -> 90.67
```

Формула находится в `vip_fovweapon.cpp`:

```cpp
viewmodel = 68.0f * (worldFOV / 90.0f);
```

Если визуально оружие получается слишком далеко, уменьши `kBaseViewmodelFOV` (например до 60-64) или замени формулу на свою.

## Команды для теста

```text
!fovweapon 110
!fovweaponinfo
```

`!fovweapon 110` сразу выставляет world FOV и рассчитанный viewmodel FOV.

`!fovweaponinfo` показывает текущие значения и найденные schema offsets. Это удобно после обновлений CS2.

## Важно

Это исходный проект. Для получения `.so` нужны Metamod:Source, HL2SDK CS2, AMBuild и зависимости, которые ожидает `configure.py`/`AMBuildScript`.

Я не могу проверить визуальный результат на живом клиенте CS2 из этой среды. Серверное поле `m_flViewmodelFOV` найдено в предоставленном Linux `libserver.so`, но окончательно подтвердить, что текущий клиент применяет его именно к рендеру оружия, нужно на тестовом сервере.


## Тест без VIP

Начиная с 1.1 команда `!fovweapon <FOV>` специально не проверяет VIP-статус, чтобы можно было проверить серверные schema-поля на любом тестовом игроке. VIP-меню и feature `FOV` по-прежнему работают через VIP Core.

После `!fovweapon 110` выполните `!fovweaponinfo`. Ожидаемо: `world=110 viewmodel=83.11`. Если числа меняются, но картинка оружия нет — значит запись/репликация поля проходит, но клиент не использует его так, как ожидается.

## Имя выходного файла

Проект и GitHub Actions настроены на единое имя:

```text
vip_viewmodelfov.so
```

`configure.py` в workflow явно получает `--plugin-name vip_viewmodelfov --plugin-alias vip_viewmodelfov`, поэтому проверка сборки и создаваемый `.so` совпадают.

## Диагностика CameraServices / viewmodel offsets (v1.2-diag)

В этой версии добавлены команды без VIP-проверки специально для теста:

```text
!fovdiag
!fovcam 120
!fovdiag
!fovoffset 10 0 0
!fovdiag
```

Что смотреть:

* `!fovcam 120` должен написать в чат `camera=120 start=120`. После этого проверить глазами, изменился ли FOV/оружие.
* `!fovoffset 10 0 0` должен написать новые X/Y/Z. Проверить глазами, сдвинулось ли оружие.
* Для возврата offsets можно попробовать `!fovoffset 0 0 0`.
* `!fovweapon 120` по-прежнему меняет `m_iDesiredFOV` и `m_flViewmodelFOV`.

Offsets для CameraServices и viewmodel полей ищутся через SchemaSystem во время запуска, а не зашиты числом.


## Версия 1.3 — постоянный CameraServices FOV

По реальному тесту на сервере `m_iFOV/m_iFOVStart` в `CCSPlayerBase_CameraServices`
дают нужный эффект: отдаляется и мир, и оружие. CS2 сбрасывает CameraServices при
смене активного оружия. Эта версия хранит выбранный FOV и автоматически
возвращает его после `weapon_switch` и `item_equip` (на следующем и ещё одном
кадре).

Тест:

```text
!fovcam 120
```

После этого несколько раз переключить нож/пистолет/основное оружие. FOV должен
оставаться 120. Проверка:

```text
!fovdiag
```

Для временного отключения автоповтора тестовой команды:

```text
!fovcam off
```

В VIP-меню используется тот же постоянный механизм автоматически.
