# VIP_FOVWeapon — Native Detour v4 (Linux)

Эта версия больше не восстанавливает FOV **после** сброса.
Она перехватывает внутренний `CameraServices::SetFOV` в `libserver.so` и для игрока с активным VIP FOV заменяет только вызов `targetFOV=0` на выбранное значение **до записи и сетевой отправки**.

## Перед тестом

Оставь только один FOV-модуль: `vip_viewmodelfov.so`. Полностью перезапусти сервер.

В консоли сервера должны появиться строки примерно:

```
[VIP-FOVDetour] native SetFOV found: ... + 0x14EB7D0.
[VIP-FOVDetour] SetFOV detour INSTALLED at libserver.so+0x14EB7D0.
```

RVA **не зашит**: функция ищется по машинной сигнатуре и runtime Schema offsets. Если после обновления сигнатура не совпадёт ровно один раз, hook не установится.

## Команды теста

```
!fovhook 120
!fovhookdiag
!fovhook off
```

После `!fovhook 120` несколько раз переключи нож/пистолет/автомат.

Диагностика:

```
[FOV4] target=120 cam=120/120 detour=YES resetsBlocked=...
```

`resetsBlocked` должен расти при тех действиях, где движок раньше сбрасывал FOV. Важнее всего: экран не должен успевать дёрнуться к стандартному FOV.

`emergency` в норме должен оставаться 0. Если он растёт — какой-то путь пишет CameraServices напрямую, обходя SetFOV.

## Zoom оружия

Detour не меняет ненулевые target FOV движка. Поэтому AWP/Scout zoom проходит штатно. Когда игра пытается вернуться в `0`, для VIP игрока возврат идёт сразу к выбранному FOV.

## Важно

Inline detour — низкоуровневый Linux-механизм. Он устанавливается только при точном уникальном совпадении сигнатуры. При `matches=0`/`matches>1` команда откажется включаться вместо вызова неизвестного адреса.
